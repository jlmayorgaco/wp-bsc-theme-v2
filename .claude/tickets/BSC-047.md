# BSC-047 — Monitoreo y alertas básicas de producción

## Objetivo
Configurar monitoreo básico del sitio en producción: alerta si el sitio cae, alerta si el SSL va a expirar, alerta si el disco supera el 80%, alerta si un backup falla.

## Contexto
Sin monitoreo, una caída del sitio puede pasar horas sin que nadie lo note. Es una prioridad de producción, especialmente para un ecommerce donde cada minuto caído es ingreso perdido.

## Archivos a revisar/crear
- Nuevo `scripts/monitor-health.sh` — script de health check básico
- Nuevo `docs/monitoring-setup.md` — guía de configuración del monitoreo

## Implementación exacta
1. **Uptime monitoring** (uptime externo): registrar el sitio en UptimeRobot (gratuito) o BetterUptime. Configurar alerta de email/SMS al caer. Documentar la configuración en `docs/monitoring-setup.md`.

2. Crear `scripts/monitor-health.sh` para chequeos en el servidor:
   ```bash
   #!/bin/bash
   SITE_URL="https://bubbleskincare.co"
   ADMIN_EMAIL="admin@bubbleskincare.co"
   LOG_FILE="/var/log/bsc-monitor.log"
   
   # Check 1: HTTP status
   HTTP_CODE=$(curl -s -o /dev/null -w "%{http_code}" $SITE_URL)
   if [ "$HTTP_CODE" != "200" ]; then
       echo "[$(date)] ALERT: Site returned HTTP $HTTP_CODE" >> $LOG_FILE
       echo "BSC ALERT: Site returned HTTP $HTTP_CODE" | mail -s "BSC Site Down" $ADMIN_EMAIL
   fi
   
   # Check 2: Disk usage
   DISK_USAGE=$(df / | awk 'NR==2{print $5}' | sed 's/%//')
   if [ "$DISK_USAGE" -gt 80 ]; then
       echo "[$(date)] ALERT: Disk at ${DISK_USAGE}%" >> $LOG_FILE
       echo "BSC ALERT: Disk at ${DISK_USAGE}%" | mail -s "BSC Disk Warning" $ADMIN_EMAIL
   fi
   
   # Check 3: SSL expiry (30 days warning)
   SSL_EXPIRY=$(echo | openssl s_client -connect bubbleskincare.co:443 2>/dev/null | openssl x509 -noout -enddate | cut -d= -f2)
   EXPIRY_EPOCH=$(date -d "$SSL_EXPIRY" +%s)
   NOW_EPOCH=$(date +%s)
   DAYS_LEFT=$(( ($EXPIRY_EPOCH - $NOW_EPOCH) / 86400 ))
   if [ "$DAYS_LEFT" -lt 30 ]; then
       echo "[$(date)] ALERT: SSL expires in $DAYS_LEFT days" >> $LOG_FILE
       echo "BSC ALERT: SSL expires in $DAYS_LEFT days" | mail -s "BSC SSL Warning" $ADMIN_EMAIL
   fi
   ```
3. Agregar al crontab (ejecutar cada 15 minutos):
   ```bash
   */15 * * * * /path/to/scripts/monitor-health.sh
   ```
4. Crear `docs/monitoring-setup.md` documentando:
   - Cómo configurar UptimeRobot.
   - Cómo instalar el cron del script de monitoreo.
   - Cómo verificar los logs de monitoreo.
   - Qué hacer en cada tipo de alerta.

## Qué NO se acepta como solución
- Solo monitoreo externo sin scripts de servidor (o viceversa).
- Sin alerta de SSL.
- Sin alerta de disco.

## Requerimientos
- El email de alerta debe llegar en menos de 20 minutos desde que ocurre el problema.
- Los logs de monitoreo deben ser revisables.

## Criterios de aceptación
- El sitio tiene monitoreo de uptime externo configurado (ej. UptimeRobot).
- El script de monitoreo verifica: HTTP status, disco, SSL.
- Las alertas llegan al email configurado.
- Los logs tienen registros de cada check.

## QA manual
- Simular caída: poner el sitio en modo mantenimiento → el monitor debe alertar.
- Ejecutar `monitor-health.sh` manualmente → verificar log.
- Verificar que UptimeRobot está activo y haciendo checks.

# BSC-049 — Cache y optimización de servidor

## Objetivo
Mejorar el TTFB y la estabilidad general configurando caché de páginas, caché de browser, compresión gzip/brotli y object cache si el hosting lo permite.

## Contexto
El target de performance es TTFB < 500ms y carga total < 2s. Sin caché de servidor el PHP se ejecuta completo en cada request. WooCommerce complica el page cache (carrito, usuario logueado) pero las páginas estáticas (home, shop, categorías) sí pueden cachearse.

## Archivos a revisar
- `.htaccess` — headers de browser cache y gzip
- `wp-config.php` — object cache si aplica
- Plugin de caché a seleccionar/configurar (documentar, no implementar código de plugin)

## Implementación exacta
1. **Browser cache** en `.htaccess` (Apache):
   ```apache
   # Browser Cache
   <IfModule mod_expires.c>
       ExpiresActive On
       ExpiresByType image/jpeg "access plus 1 year"
       ExpiresByType image/png "access plus 1 year"
       ExpiresByType image/webp "access plus 1 year"
       ExpiresByType text/css "access plus 1 month"
       ExpiresByType application/javascript "access plus 1 month"
       ExpiresByType font/woff2 "access plus 1 year"
   </IfModule>
   ```
2. **Gzip** en `.htaccess`:
   ```apache
   <IfModule mod_deflate.c>
       AddOutputFilterByType DEFLATE text/html text/css application/javascript application/json
   </IfModule>
   ```
3. **Page cache**: recomendar e instalar WP Super Cache o W3 Total Cache. Configurar para:
   - Cachear solo páginas no logueadas.
   - Excluir: cart, checkout, my-account, todas las URLs con `?`.
   - TTL de caché: 2-4 horas.
4. **Object cache**: si el hosting tiene Redis o Memcached disponible, instalar el drop-in correspondiente. Documentar cómo verificar si está disponible.
5. Crear `docs/cache-config.md` con la configuración exacta usada y las URLs excluidas del caché.

## Qué NO se acepta como solución
- Cachear páginas del carrito o checkout (rompe WooCommerce).
- Caché sin lista de exclusiones para WooCommerce.
- No documentar qué se configuró.

## Requerimientos
- Las páginas de cart, checkout y my-account nunca se cachean.
- Los assets (CSS, JS, imágenes) tienen headers de caché de largo plazo.
- Los cambios en `.htaccess` no rompen el sitio.

## Criterios de aceptación
- Lighthouse Performance muestra mejora en TTFB.
- Los assets tienen headers `Cache-Control` correctos.
- La home carga con menos de 500ms de TTFB (con caché activo).
- El checkout sigue funcionando correctamente (no cacheado).

## QA manual
- Medir TTFB en la home con GTmetrix o Lighthouse → antes y después.
- DevTools → Network → imagen JPEG → headers deben mostrar `Cache-Control: max-age=...`.
- Verificar que el checkout NO está cacheado (agregar al carrito → refrescar → el carrito sigue igual).
- Probar con usuario logueado → la sesión no debe ser cacheada.

# BSC-032 — Estados de pedido custom simplificados

## Objetivo
Definir e implementar el set final de estados de pedido BSC en WooCommerce, visibles en el admin custom y en el progress bar del frontend, sin romper emails ni analytics.

## Contexto
WooCommerce tiene estados estándar que no coinciden con el lenguaje operativo de BSC. El PDF y NEW_FEATURES.md piden estados en español acorde al flujo real del negocio. Los estados deben mapearse a WooCommerce correctamente.

## Archivos a revisar
- `inc/woocommerce.php` — registrar custom statuses
- `components/orders/order-progress-bar.php` — barra de progreso en el frontend
- `style.css` — colores de los estados

## Implementación exacta
1. En `inc/woocommerce.php`, registrar los estados custom:
   ```php
   add_action('init', 'bsc_register_order_statuses');
   function bsc_register_order_statuses() {
       register_post_status('wc-preparing', [
           'label'                     => 'En preparación',
           'public'                    => true,
           'show_in_admin_status_list' => true,
           'label_count'               => _n_noop('En preparación (%s)', 'En preparación (%s)'),
       ]);
       register_post_status('wc-shipped', [
           'label'                     => 'Enviado',
           'public'                    => true,
           'show_in_admin_status_list' => true,
           'label_count'               => _n_noop('Enviado (%s)', 'Enviados (%s)'),
       ]);
   }
   add_filter('wc_order_statuses', 'bsc_add_order_statuses_to_woo');
   function bsc_add_order_statuses_to_woo($order_statuses) {
       $new_statuses = [];
       foreach ($order_statuses as $key => $status) {
           $new_statuses[$key] = $status;
           if ($key === 'wc-processing') {
               $new_statuses['wc-preparing'] = 'En preparación';
           }
       }
       $new_statuses['wc-shipped'] = 'Enviado';
       return $new_statuses;
   }
   ```
2. Set completo de estados BSC:
   - `wc-processing` → "Pago Recibido" (reusar el nativo)
   - `wc-preparing` → "En preparación" (custom)
   - `wc-shipped` → "Enviado" (custom)
   - `wc-completed` → "Entregado" (reusar el nativo, renombrar label)
   - `wc-cancelled` → "Cancelado" (reusar nativo)
   - `wc-failed` → "Fallido" (reusar nativo)
3. En CSS: definir colores para los estados en la barra de progreso y chips:
   - Pago Recibido: verde
   - En preparación: amarillo
   - Enviado: azul
   - Entregado: verde oscuro
   - Cancelado: rojo
   - Fallido: gris oscuro
4. Actualizar `components/orders/order-progress-bar.php` para que use estos estados en el orden correcto.

## Qué NO se acepta como solución
- Renombrar estados nativos de WooCommerce de forma que rompa funcionalidad core.
- Eliminar estados nativos necesarios para WooCommerce (como `pending`, `failed`).

## Requerimientos
- Los estados custom deben registrarse con `register_post_status`.
- Los estados deben aparecer en `wc_order_statuses` para que WooCommerce los reconozca.
- No romper el flujo de emails de WooCommerce core.

## Criterios de aceptación
- Los estados BSC aparecen en el dropdown de estados del admin.
- La barra de progreso del frontend usa los estados BSC.
- Los colores de estado son correctos (verde, amarillo, azul, etc.).
- Los emails de WooCommerce siguen funcionando para los estados nativos.

## QA manual
- Crear pedido de prueba → ver en admin BSC Orders → verificar dropdown con estados BSC.
- Cambiar a "En preparación" → verificar que se guarda correctamente.
- Ver el pedido en Mi Cuenta → verificar la barra de progreso con el estado correcto.
- Completar un pedido → verificar que el email de WooCommerce se envía.

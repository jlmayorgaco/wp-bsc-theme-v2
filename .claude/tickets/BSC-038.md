# BSC-038 — Optimizar búsqueda AJAX: unificar triple query en una sola

## Objetivo
Reducir las 3 queries separadas de la búsqueda AJAX (título, SKU, marca) a 1 query optimizada. Agregar debounce más agresivo, caché con transients y límite de resultados.

## Contexto
El issue (PERF-001) detecta que `inc/ajax/search-actions.php` ejecuta 3 `WP_Query` separadas por cada búsqueda: una para título/descripción, una para SKU y una para categoría/marca. Con muchos productos esto es muy lento. El debounce actual es 350ms pero sin caché.

## Archivos a revisar
- `inc/ajax/search-actions.php` — handler de búsqueda
- `js/search.js` — debounce y manejo de resultados

## Implementación exacta
1. En `inc/ajax/search-actions.php`, reescribir la lógica de búsqueda:
   ```php
   $query = sanitize_text_field($_POST['query'] ?? '');
   if (strlen($query) < 2) wp_send_json_error();
   
   $cache_key = 'bsc_search_' . md5($query);
   $cached = get_transient($cache_key);
   if ($cached !== false) {
       wp_send_json_success($cached);
   }
   
   // Una sola query con múltiples criterios
   $args = [
       'post_type'      => 'product',
       'post_status'    => 'publish',
       'posts_per_page' => 8,
       's'              => $query, // título + descripción
       'meta_query'     => [
           'relation' => 'OR',
           ['key' => '_sku', 'value' => $query, 'compare' => 'LIKE'],
       ],
       'tax_query' => [
           ['taxonomy' => 'product_cat', 'field' => 'name', 'terms' => $query, 'operator' => 'LIKE'],
       ],
   ];
   $results_query = new WP_Query($args);
   // ... formatear resultados ...
   
   set_transient($cache_key, $results, 15 * MINUTE_IN_SECONDS);
   wp_send_json_success($results);
   ```
2. En `js/search.js`: asegurarse de que el debounce es de al menos 400ms.
3. Agregar un cache del lado del cliente: un objeto JS `searchCache = {}` que guarda los últimos 10 resultados de búsquedas únicas por session, para no repetir requests idénticos.
4. Limitar los resultados a máximo 8 items.

## Qué NO se acepta como solución
- Mantener las 3 queries separadas.
- Caché sin TTL (nunca expira).
- Sin límite de resultados por request.

## Requerimientos
- El transient de caché tiene TTL de 15 minutos.
- Búsquedas de menos de 2 caracteres no hacen request al servidor.
- El resultado máximo es 8 productos.

## Criterios de aceptación
- La búsqueda hace 1 request (no 3) al servidor por búsqueda.
- Búsqueda repetida del mismo término usa caché (sin request nuevo).
- El tiempo de respuesta es < 500ms para búsquedas comunes.
- Los resultados siguen incluyendo título, SKU y categoría como criterios.

## QA manual
- Abrir DevTools → Network → buscar un producto → verificar 1 solo request AJAX.
- Buscar el mismo término dos veces → el segundo no debe generar request (caché cliente).
- Buscar por SKU → debe encontrar el producto.
- Buscar por nombre de marca → debe encontrar productos de esa marca.

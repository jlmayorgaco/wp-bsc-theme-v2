# BSC-043 — Seguridad formularios: nonce, sanitización, rate limiting y CSRF

## Objetivo
Auditar y asegurar todos los formularios AJAX del sitio (contacto, newsletter, creators, login custom, checkout, carrito) con nonces, sanitización completa de inputs, rate limiting básico y protección CSRF.

## Contexto
El issue lista problemas de seguridad en formularios/AJAX. Los handlers en `inc/ajax/` pueden tener sanitización incompleta, nonces faltantes o sin rate limiting. Es una prioridad para producción.

## Archivos a revisar
- `inc/ajax/cart-actions.php`
- `inc/ajax/checkout-actions.php`
- `inc/ajax/coupons-actions.php`
- `inc/ajax/newsletter-actions.php`
- `inc/ajax/creator-actions.php`
- `inc/ajax/search-actions.php`
- `inc/ajax/filters-actions.php`
- `inc/ajax/review-summary-actions.php`
- `page-login.php`, `page-register.php` — formularios de login/registro custom

## Implementación exacta
1. **Auditar cada handler AJAX** y verificar que tiene:
   - `check_ajax_referer('nombre_nonce', 'nonce')` al inicio.
   - Sanitización de todos los inputs: `sanitize_text_field()`, `sanitize_email()`, `absint()`, `esc_url_raw()` según el tipo.
   - Control de capability donde aplica: `current_user_can('...')`.
   - Guard `if (!defined('ABSPATH')) exit;` al inicio del archivo.
2. **Rate limiting básico** para formularios de contacto, newsletter y creators:
   ```php
   function bsc_check_rate_limit($key, $ttl = 60) {
       $transient_key = 'bsc_rate_' . md5($key . $_SERVER['REMOTE_ADDR']);
       if (get_transient($transient_key)) {
           wp_send_json_error(['message' => 'Demasiadas solicitudes. Espera un momento.']);
       }
       set_transient($transient_key, 1, $ttl);
   }
   ```
3. **Login/registro custom**: verificar que `page-login.php` y `page-register.php` usan `wp_login()` / `wp_create_user()` con nonces y no procesan contraseñas directamente.
4. **Output escaping**: verificar que cualquier dato del usuario que se muestra en HTML usa `esc_html()`, `esc_attr()`, `esc_url()` según el contexto.
5. Crear checklist de seguridad en `.claude/security-checklist.md` con el estado de cada handler.

## Qué NO se acepta como solución
- Handler AJAX sin nonce aunque sea de solo lectura.
- Inputs numéricos sin `absint()` o `intval()`.
- Emails sin `sanitize_email()` y validación con `is_email()`.

## Requerimientos
- Todos los handlers de escritura (cart, checkout, contact) deben tener nonce.
- Los handlers de lectura (search, filters) deben tener nonce o al menos `check_ajax_referer` con nonce de página.
- Rate limiting para: contact, newsletter, creators (máx 1 envío/60s por IP).

## Criterios de aceptación
- Todos los handlers AJAX tienen `check_ajax_referer`.
- Todos los inputs de usuario son sanitizados antes de usarse.
- Los formularios de contacto/newsletter/creators tienen rate limiting.
- El checklist de seguridad documenta el estado de cada handler.

## QA manual
- Enviar request AJAX sin nonce desde DevTools → debe retornar error.
- Intentar XSS en el campo de búsqueda (`<script>alert(1)</script>`) → no debe ejecutarse.
- Enviar el formulario de contacto 2 veces en < 60 segundos → segunda vez debe dar error.
- Verificar en DevTools que las respuestas AJAX no exponen datos sensibles.

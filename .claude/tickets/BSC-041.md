# BSC-041 — Versionado de assets sin filemtime en producción

## Objetivo
Reemplazar el versionado de assets basado en `filemtime()` (que hace I/O de disco por cada request) por una versión estática basada en una constante o el hash del theme, para reducir operaciones de I/O innecesarias en producción.

## Contexto
El issue (PERF-004) indica que `enqueue-scripts.php` usa `filemtime()` para versionar los assets CSS y JS. En cada request de cada página esto ejecuta una operación de I/O para leer la fecha de cada archivo. En producción con mucho tráfico esto suma.

## Archivos a revisar
- `inc/scripts/enqueue-scripts.php` — donde se hace el enqueue de scripts y estilos

## Implementación exacta
1. En `functions.php` o `inc/setup/theme-setup.php`, definir la versión del theme:
   ```php
   define('BSC_THEME_VERSION', wp_get_theme()->get('Version'));
   // O usar un hash estático que se actualiza con cada deploy:
   // define('BSC_THEME_VERSION', '1.2.0');
   ```
2. En `inc/scripts/enqueue-scripts.php`: reemplazar `filemtime(get_template_directory() . '/path/to/file')` por `BSC_THEME_VERSION` o la versión del `style.css`:
   ```php
   // ANTES:
   wp_enqueue_style('bsc-style', get_stylesheet_uri(), [], filemtime(get_stylesheet_directory() . '/style.css'));
   
   // DESPUÉS:
   wp_enqueue_style('bsc-style', get_stylesheet_uri(), [], BSC_THEME_VERSION);
   ```
3. Para que el versionado funcione en producción sin I/O: actualizar manualmente `BSC_THEME_VERSION` cuando se haga un deploy.
4. En entorno local de desarrollo (opcional): mantener `filemtime()` solo si `WP_DEBUG` está activo:
   ```php
   $ver = ( defined('WP_DEBUG') && WP_DEBUG ) ? filemtime(get_template_directory() . '/style.css') : BSC_THEME_VERSION;
   ```

## Qué NO se acepta como solución
- Usar la misma versión estática para siempre sin actualizarla en cada deploy (los browsers mantendrán caché con la versión vieja).
- Eliminar el versionado completamente.

## Requerimientos
- La versión debe cambiar con cada deploy para invalidar caché del browser.
- El mecanismo no debe hacer I/O de disco en producción.

## Criterios de aceptación
- Los assets se enqueuen con la versión de `BSC_THEME_VERSION`.
- No hay llamadas a `filemtime()` en producción (salvo que `WP_DEBUG` esté activo).
- El browser recibe headers de caché correctos.

## QA manual
- Revisar código de `enqueue-scripts.php` → no debe haber `filemtime()` en producción.
- Verificar en DevTools → Network → los scripts y estilos tienen `?ver=X.X.X`.
- Cambiar `BSC_THEME_VERSION` → verificar que los assets se recargan (nueva versión en URL).

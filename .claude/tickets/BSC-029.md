# BSC-029 — Crear roles custom: Admin, Operador y Empleado

## Objetivo
Crear roles custom de WordPress (`bsc_operator`, `bsc_employee`) con capabilities específicas y restricciones de acceso al admin, para que el equipo operativo solo vea lo que necesita.

## Contexto
El cliente pide Admin total, Operativo con acceso solo a pedidos/tareas permitidas, y Empleado con acceso a pedidos + productos. NEW_FEATURES.md tiene el código base. Los roles deben crearse al activar el theme y eliminarse al desactivarlo (o quedar persistentes con guard).

## Archivos a revisar
- Nuevo `includes/class-bsc-roles.php` — clase de gestión de roles
- `inc/setup/theme-setup.php` — para el hook de activación
- `functions.php` — para requerir el nuevo archivo

## Implementación exacta
1. Crear `includes/class-bsc-roles.php`:
   ```php
   class BSC_Roles {
       public static function create() {
           if ( ! get_role('bsc_operator') ) {
               add_role('bsc_operator', 'BSC Operador', [
                   'read'        => true,
                   'edit_orders' => true,
               ]);
           }
           if ( ! get_role('bsc_employee') ) {
               add_role('bsc_employee', 'BSC Empleado', [
                   'read'          => true,
                   'edit_orders'   => true,
                   'edit_products' => true,
               ]);
           }
       }
       public static function remove() {
           remove_role('bsc_operator');
           remove_role('bsc_employee');
       }
   }
   ```
2. En `inc/setup/theme-setup.php`: llamar `BSC_Roles::create()` en el hook `after_switch_theme`.
3. Crear `includes/class-bsc-permissions.php` con la lógica de restricción de acceso al admin:
   ```php
   class BSC_Permissions {
       public static function init() {
           add_action('admin_init', [__CLASS__, 'restrict_admin_access']);
       }
       public static function restrict_admin_access() {
           if ( ! is_admin() || wp_doing_ajax() ) return;
           $user = wp_get_current_user();
           if ( in_array('bsc_operator', $user->roles) ) {
               $page = $_GET['page'] ?? '';
               if ( $page !== 'bsc-orders' ) {
                   wp_redirect( admin_url('admin.php?page=bsc-orders') );
                   exit;
               }
           }
           if ( in_array('bsc_employee', $user->roles) ) {
               $page = $_GET['page'] ?? '';
               $allowed = ['bsc-orders', 'bsc-products'];
               if ( ! in_array($page, $allowed) ) {
                   wp_redirect( admin_url('admin.php?page=bsc-orders') );
                   exit;
               }
           }
       }
   }
   BSC_Permissions::init();
   ```
4. Requerir ambos archivos desde `functions.php`.

## Qué NO se acepta como solución
- Crear roles con `add_role()` directamente en `functions.php` sin guard (se ejecuta en cada request).
- Roles con capabilities excesivas.
- Sin lógica de restricción de acceso al admin.

## Requerimientos
- Los roles solo se crean si no existen (guard con `get_role()`).
- La restricción de admin no aplica a `wp_doing_ajax()` (evita bloquear AJAX).
- El rol `administrator` no debe verse afectado.

## Criterios de aceptación
- Un usuario con rol `bsc_operator` solo puede acceder a la página `bsc-orders` en el admin.
- Un usuario con rol `bsc_employee` puede acceder a `bsc-orders` y `bsc-products`.
- El admin (administrator) ve todo sin restricciones.
- Los roles existen en la base de datos tras activar el theme.

## QA manual
- Crear usuario con rol `bsc_operator` → loguearse → intentar ir a Woo Admin → debe redirigir a BSC Orders.
- Crear usuario con rol `bsc_employee` → loguearse → intentar ir a Configuración → debe redirigir.
- Verificar que admin ve todo normal.
- Desactivar/reactivar el theme → roles siguen existiendo (guard funciona).

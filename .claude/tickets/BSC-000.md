# BSC-000 — Baseline técnico y entorno de trabajo

## Objetivo
Crear una base segura antes de iterar en features. Documentar la estructura real del theme, establecer convenciones de ramas y activar entorno de staging con backup restaurable.

## Contexto
El proyecto no tiene entorno de staging documentado, ni checklist de smoke test, ni convención de ramas definida. Cualquier cambio sin esta base aumenta el riesgo de romper producción.

## Archivos a revisar
- `functions.php`
- `inc/setup/theme-setup.php`
- `inc/scripts/enqueue-scripts.php`
- `README.md` (crear si no existe)
- `CHANGELOG.md` (crear si no existe)

## Implementación exacta
1. Documentar en `README.md` las páginas críticas: front-page, header/footer, product card, product detail, cart, checkout, my account, bubble points, admin custom.
2. Documentar en `README.md` los AJAX handlers en `inc/ajax/` y los overrides de WooCommerce en `woocommerce/`.
3. Crear `CHANGELOG.md` con entrada inicial para el estado actual del theme.
4. Crear checklist de smoke test manual en `.claude/qa-checklist.md` cubriendo: navegación, cart, checkout, my account, mobile.
5. Fijar convención de ramas en README: `fix/BSC-XXX-descripcion`, `feat/BSC-XXX-descripcion`, `refactor/BSC-XXX-descripcion`.
6. Activar modo staging (documentar el proceso para el equipo).
7. Crear snapshot/backup del theme antes de iniciar el sprint.

## Qué NO se acepta como solución
- Agregar nuevas features o cambios de código en este ticket.
- Modificar lógica de negocio.

## Requerimientos
- No tocar código PHP o JS del theme en este ticket.
- Todo entregable es documentación o configuración de entorno.

## Criterios de aceptación
- Existe `README.md` con estructura y páginas críticas documentadas.
- Existe `CHANGELOG.md` con entrada inicial.
- Existe checklist QA manual en `.claude/qa-checklist.md`.
- Existe convención de ramas documentada.
- Existe backup restaurable del estado actual del theme.

## QA manual
- Verificar que `README.md` se puede leer y tiene las rutas correctas.
- Verificar que el checklist QA cubre los flujos críticos.
- Restaurar snapshot en entorno local y confirmar que el sitio funciona.

# BSC-012 — Ícono de perfil mobile debe linkear a Profile/Orders

## Objetivo
Corregir la navegación del ícono de perfil en el header mobile para que lleve al usuario a su perfil/pedidos si está logueado, o a login si no lo está.

## Contexto
El PDF pide que el ícono de perfil mobile lleve a "profile orders". Actualmente el link puede estar roto, apuntar a la home, o no distinguir entre guest y logged user.

## Archivos a revisar
- `components/header.php` — ícono de perfil en la sección mobile del header

## Implementación exacta
1. En `components/header.php`, localizar el ícono de perfil en el header mobile.
2. Envolver o actualizar su `href` con lógica condicional:
   ```php
   $profile_url = is_user_logged_in()
       ? wc_get_account_endpoint_url('orders')
       : wp_login_url( get_permalink() );
   ```
3. El `href` del ícono debe usar `$profile_url`.
4. Agregar `aria-label` apropiado: "Mi cuenta" o "Ingresar".

## Qué NO se acepta como solución
- Link hardcodeado a una URL fija.
- No distinguir entre guest y logged user.

## Requerimientos
- Usuario logueado → va a la página de pedidos de Mi Cuenta.
- Usuario no logueado → va a la página de login con redirect de vuelta.

## Criterios de aceptación
- Usuario logueado: ícono de perfil mobile → `/mi-cuenta/orders/` (o equivalente).
- Usuario no logueado: ícono de perfil mobile → página de login.
- Después de login, el usuario regresa a la página donde estaba.

## QA manual
- Sin login: tap en ícono de perfil mobile → debe ir a login.
- Con login: tap en ícono → debe ir a lista de pedidos.
- Verificar URL de destino en ambos casos.

# BSC-042 — Imágenes responsive: srcset, lazy load y placeholders correctos

## Objetivo
Mejorar la carga de imágenes en mobile implementando `srcset`, `sizes`, `loading="lazy"` en todas las imágenes del theme, y verificando que los tamaños de imagen de WordPress están correctamente registrados para no servir imágenes sobredimensionadas.

## Contexto
El issue (PERF-005) indica que las imágenes pueden no tener `srcset`, `loading="lazy"` o tamaños correctos, lo que afecta el LCP y el performance móvil. WordPress genera srcset automáticamente pero solo si los image sizes están bien registrados.

## Archivos a revisar
- `inc/setup/theme-setup.php` — registro de tamaños de imagen custom
- `components/products/card.php` — imagen del card de producto
- `components/swiper.php` — imágenes del hero slider
- `components/products/slider.php` — imagen en el slider de productos
- `woocommerce/single-product.php` — imagen del producto

## Implementación exacta
1. En `inc/setup/theme-setup.php`: verificar y registrar los tamaños de imagen necesarios:
   ```php
   add_image_size('bsc-card', 400, 400, true);        // product card cuadrado
   add_image_size('bsc-hero', 1440, 600, true);       // hero slider
   add_image_size('bsc-thumb', 120, 120, true);       // thumbnails
   ```
2. En `components/products/card.php`: usar `wp_get_attachment_image()` que genera automáticamente `srcset` y `sizes`:
   ```php
   echo wp_get_attachment_image(
       $product->get_image_id(),
       'bsc-card',
       false,
       ['loading' => 'lazy', 'class' => 'product-card__image']
   );
   ```
3. En `components/swiper.php` (slide 0): mantener `loading="eager"` y `fetchpriority="high"` para el LCP. Slides 1+ deben tener `loading="lazy"`.
4. En `components/products/slider.php`: verificar uso de `wp_get_attachment_image()` con `loading="lazy"`.
5. Añadir soporte a `add_theme_support('post-thumbnails')` si no está (necesario para que WP procese image sizes).
6. Correr `wp_generate_attachment_metadata()` solo es necesario si se agregan nuevos tamaños a imágenes ya existentes (hacerlo via WP-CLI: `wp media regenerate`).

## Qué NO se acepta como solución
- `<img>` sin `loading` attribute en imágenes debajo del fold.
- Imágenes del hero con `loading="lazy"` (el primer slide es LCP y necesita `eager`).
- Usar `get_the_post_thumbnail_url()` y construir `<img>` manualmente sin `srcset`.

## Requerimientos
- El hero slide 0 siempre tiene `loading="eager"` y `fetchpriority="high"`.
- Todas las demás imágenes del theme tienen `loading="lazy"`.
- Los image sizes BSC están registrados en WordPress.

## Criterios de aceptación
- Las cards de productos tienen `srcset` y `loading="lazy"`.
- El slide 0 del hero tiene `fetchpriority="high"`.
- Los image sizes están registrados: `bsc-card`, `bsc-hero`, `bsc-thumb`.
- Lighthouse Performance en mobile mejora (objetivo: LCP < 2.5s).

## QA manual
- Inspeccionar una card de producto en el HTML → verificar `srcset`, `sizes`, `loading="lazy"`.
- Inspeccionar el primer slide del hero → `loading="eager"`, `fetchpriority="high"`.
- Correr Lighthouse en mobile → LCP debería mejorar.
- Verificar en DevTools → Network → las imágenes de cards no se cargan hasta el scroll.

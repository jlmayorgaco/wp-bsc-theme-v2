# BSC-052 — Documentación operativa y técnica completa del proyecto

## Objetivo
Dejar documentación suficiente para que cualquier desarrollador pueda entender, mantener y desplegar el proyecto BSC sin asistencia: README técnico actualizado, CHANGELOG, runbook de deploy, runbook de backup/restore y guía de estructura del código.

## Contexto
El review marcó falta crítica de documentación. Sin documentación técnica correcta, cada sesión de desarrollo (o cada nuevo desarrollador) pierde tiempo reconstruyendo contexto. Este ticket cierra el ciclo de documentación iniciado en BSC-000 y BSC-044.

## Archivos a revisar/crear
- `README.md` — documentación técnica principal (actualizar lo de BSC-044)
- `CHANGELOG.md` — historial de cambios (actualizar)
- `docs/deploy.md` — runbook de deploy
- `docs/architecture.md` — guía de arquitectura del theme

## Implementación exacta
1. Crear `docs/deploy.md` con el proceso de deploy a producción:
   - Pre-deploy: crear backup, activar modo mantenimiento, correr QA checklist en staging.
   - Deploy: `git pull origin main`, `wp cache flush`, limpiar transients: `wp transient delete --all`.
   - Post-deploy: desactivar modo mantenimiento, smoke tests manuales.
   - Rollback: restaurar desde backup si algo falla.
2. Crear `docs/architecture.md` con:
   - Mapa de archivos críticos y su responsabilidad.
   - Flujo de datos: request → template → components → AJAX → DB.
   - Lista de AJAX endpoints custom con sus nonces, capabilities y archivos.
   - Lista de hooks custom de WooCommerce usados.
   - Sistema de Bubble Points: cómo funciona, cómo se acumulan y canjean.
3. Actualizar `README.md` para incluir link a todos los documentos en `docs/`.
4. Actualizar `CHANGELOG.md` con todas las entradas de tickets completados hasta la fecha.

## Qué NO se acepta como solución
- Documentación genérica copiada de internet.
- Documentos de deploy sin los comandos específicos del proyecto BSC.
- Sin lista de AJAX endpoints con sus nonces y capabilities.

## Requerimientos
- La documentación debe ser revisada con el código real (no inventada).
- Los comandos en los runbooks deben ser probados y funcionales.

## Criterios de aceptación
- `docs/deploy.md` tiene pasos completos de deploy y rollback.
- `docs/architecture.md` tiene mapa de archivos y flujo de datos.
- `README.md` tiene link a todos los documentos en `docs/`.
- `CHANGELOG.md` está al día con todos los tickets completados.

## QA manual
- Leer `docs/deploy.md` → un dev que nunca ha tocado el proyecto puede seguirlo.
- Leer `docs/architecture.md` → puede entender dónde está cada cosa en < 15 minutos.
- Buscar cualquier endpoint AJAX en `docs/architecture.md` → debe estar listado.

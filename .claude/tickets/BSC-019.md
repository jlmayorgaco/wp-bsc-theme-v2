# BSC-019 — Loading states en add-to-cart, checkout, filtros y cupón

## Objetivo
Agregar feedback visual de loading (spinner o estado "procesando") en todas las operaciones AJAX del sitio: add-to-cart, cambio de cantidad, checkout submit, aplicar filtros y aplicar cupón. Prevenir doble click durante operaciones.

## Contexto
El review marca ausencia de loading states como un problema de UX. Los usuarios no saben cuándo una operación está procesándose, lo que lleva a double-clicks y estados inconsistentes. Afecta add-to-cart, qty controls, coupon form, filters y checkout form.

## Archivos a revisar
- `js/cart.js` — add-to-cart y qty controls
- `js/coupons.js` — aplicar cupón
- `js/filters.js` — aplicar filtros de productos
- `js/checkout.js` — submit del checkout
- `style.css` — CSS del spinner/loading state

## Implementación exacta
1. Crear un CSS helper para estado loading en botones:
   ```css
   .bsc-loading {
       pointer-events: none;
       opacity: 0.7;
       position: relative;
   }
   .bsc-loading::after {
       content: '';
       display: inline-block;
       width: 14px;
       height: 14px;
       border: 2px solid currentColor;
       border-top-color: transparent;
       border-radius: 50%;
       animation: bsc-spin 0.6s linear infinite;
       margin-left: 8px;
       vertical-align: middle;
   }
   @keyframes bsc-spin { to { transform: rotate(360deg); } }
   ```
2. En `cart.js`: al iniciar add-to-cart → `.addClass('bsc-loading')` en el botón; al terminar (`.always()`) → `.removeClass('bsc-loading')`.
3. En `cart.js`: mismo patrón para los botones de qty `+` y `—`.
4. En `coupons.js`: mismo patrón para el botón de aplicar cupón.
5. En `filters.js`: mostrar overlay o spinner en el contenedor de productos mientras se cargan.
6. En `checkout.js`: si tiene lógica de submit custom, deshabilitar el botón de submit durante el procesamiento.
7. En todos los casos: el botón/elemento debe ser no-interactivo mientras está en estado loading (`pointer-events: none`).

## Qué NO se acepta como solución
- Usar `disabled` attribute que cambia el estilo del botón si no está previsto en el diseño.
- Loading state que no se remueve en caso de error.
- Spinner que bloquea toda la pantalla para operaciones pequeñas.

## Requerimientos
- El loading state siempre se remueve (en éxito Y en error) en el bloque `.always()` o equivalente.
- No usar `disabled` si cambia el diseño visualmente de forma no deseada.

## Criterios de aceptación
- Add-to-cart: el botón muestra spinner mientras procesa.
- Qty controls: los botones `+` y `—` no responden a doble click durante procesamiento.
- Cupón: el botón de aplicar muestra spinner durante el AJAX.
- Filtros: el contenedor de productos muestra indicador de carga.
- En caso de error: el loading state desaparece y el botón queda funcional.

## QA manual
- Click en add-to-cart → verificar spinner visible.
- Click rápido dos veces en add-to-cart → no se envían dos peticiones.
- Aplicar cupón → verificar que el botón muestra loading.
- Activar filtros → verificar indicador de carga en productos.
- Simular error de red → verificar que el loading state desaparece.

# BSC-050 — Optimización de imágenes y media pipeline

## Objetivo
Reducir el peso total de las imágenes del sitio convirtiendo a WebP donde sea posible, verificando lazy loading, corrigiendo tamaños servidos y limpiando imágenes decorativas pesadas.

## Contexto
El issue (PERF-005) y el ROADMAP identifican imágenes como uno de los principales problemas de performance. En mobile, imágenes pesadas son el factor más importante de lentitud. La meta es reducir el peso total de imágenes en la home en al menos un 50%.

## Archivos a revisar
- `inc/setup/theme-setup.php` — soporte de WebP y tamaños de imagen
- `components/swiper.php` — imágenes del hero
- `components/products/card.php` — imagen de la card
- `functions.php` — funciones de imagen custom

## Implementación exacta
1. **WebP support**: Verificar que el servidor/hosting soporta WebP. Si soporta:
   - En `inc/setup/theme-setup.php`: WordPress 5.8+ genera WebP automáticamente si el servidor tiene soporte. Solo verificar que `wp_image_editor_supports(['mime_type' => 'image/webp'])` retorna true.
   - Agregar `add_filter('image_editor_output_format', function($formats) { $formats['image/jpeg'] = 'image/webp'; $formats['image/png'] = 'image/webp'; return $formats; });` para que nuevas imágenes se guarden en WebP.
2. **Optimizar imágenes existentes**: Documentar que se debe correr `wp media regenerate --yes` via WP-CLI después de activar WebP.
3. **Lazy loading**: Verificar que todas las imágenes fuera del fold tienen `loading="lazy"` (complementa BSC-042).
4. **Imágenes decorativas pesadas**: Revisar las imágenes del mega-menú, footer y header. Verificar sus dimensiones y comprimir si pesan más de 100KB.
5. **Placeholder durante carga**: Para imágenes de cards de productos, si no tiene imagen, usar el placeholder local (`bsc_ajax.placeholder_img`) en vez de cargar una imagen pesada.
6. Crear `docs/media-optimization.md` con instrucciones para el equipo sobre cómo subir imágenes optimizadas.

## Qué NO se acepta como solución
- Forzar WebP si el servidor no lo soporta (generará imágenes rotas).
- Comprimir imágenes con calidad tan baja que se pixelen.
- Borrar imágenes originales sin tener backup.

## Requerimientos
- Verificar soporte de WebP antes de activar la conversión automática.
- Los placeholders de productos deben ser imágenes pequeñas (< 5KB).
- No afectar imágenes ya existentes que están en producción sin regenerarlas.

## Criterios de aceptación
- El servidor soporta WebP y se genera automáticamente para nuevas imágenes.
- Las imágenes de las cards tienen `loading="lazy"`.
- El placeholder de producto es pequeño y se carga rápido.
- La home carga menos MB de imágenes que antes.

## QA manual
- Subir una imagen JPEG nueva → verificar que se genera versión WebP.
- Ir a la home en DevTools → Network → imágenes → verificar que las tarjetas tienen `loading="lazy"`.
- Medir peso total de imágenes en la home con GTmetrix → debe ser menor que antes.
- Verificar que un producto sin imagen muestra el placeholder correcto.

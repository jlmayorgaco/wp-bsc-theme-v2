# BSC-044 — Documentación mínima + smoke tests + changelog

## Objetivo
Crear la documentación técnica mínima del proyecto: README con instrucciones de instalación y deploy, CHANGELOG activo, y checklist de smoke tests para QA manual post-deploy.

## Contexto
El review marca falta de documentación y testing. Sin documentación cualquier nuevo desarrollador (o el LLM en una nueva sesión) pierde tiempo reconstruyendo contexto. El CHANGELOG permite trazabilidad de qué cambió en cada deploy.

## Archivos a revisar/crear
- `README.md` — documentación técnica del proyecto
- `CHANGELOG.md` — historial de cambios
- `.claude/qa-checklist.md` — checklist de QA manual

## Implementación exacta
1. Actualizar `README.md` con:
   - Descripción del proyecto (BSC, WooCommerce theme custom).
   - Stack: WordPress, WooCommerce, PHP 8+, jQuery, Swiper v11, Font Awesome 6.5 (todos locales).
   - Requisitos: PHP >= 8.0, WooCommerce >= 7.0, WordPress >= 6.0.
   - Instalación local: clonar, activar theme, configurar staging.
   - Convención de ramas: `fix/BSC-XXX`, `feat/BSC-XXX`, `refactor/BSC-XXX`.
   - Archivos críticos y su propósito (tabla de referencia).
   - Cómo ejecutar el build de assets si aplica.
2. Mantener `CHANGELOG.md` activo con el formato:
   ```
   ## [Unreleased]
   ### Added
   - ...
   ### Fixed
   - ...
   ## [1.0.0] - 2026-04-04
   ### Added
   - Baseline inicial del theme
   ```
3. Actualizar `.claude/qa-checklist.md` con los flujos críticos a verificar antes de cada deploy:
   - Cart: agregar, modificar qty, eliminar, badge.
   - Checkout: shipping, cupón, submit, thank you.
   - Mi Cuenta: login, pedidos, editar dirección.
   - Mobile: menú, add-to-cart, checkout completo.
   - Búsqueda: resultados aparecen, sin errores JS.
   - WhatsApp: botón visible y funcional.

## Qué NO se acepta como solución
- README con solo el título del proyecto.
- CHANGELOG sin entradas reales.
- QA checklist con solo 3 items.

## Requerimientos
- El README debe ser suficiente para que un desarrollador externo entienda la estructura en 10 minutos.
- El CHANGELOG debe tener al menos las entradas de los tickets completados.

## Criterios de aceptación
- `README.md` tiene: descripción, stack, requisitos, instalación, archivos críticos.
- `CHANGELOG.md` tiene formato estándar con al menos las entradas de los tickets completados.
- `.claude/qa-checklist.md` tiene al menos 20 items de verificación.

## QA manual
- Leer el README → un nuevo dev debe poder entender cómo instalar y qué hace el theme.
- Verificar que el CHANGELOG refleja los cambios reales del proyecto.
- Usar el QA checklist antes de un deploy simulado → cubre todos los flujos críticos.

# BSC-018 — Cupón: botón negro + notice fijo en mobile

## Objetivo
Corregir la UX del cupón en checkout/cart en mobile: el botón de aplicar cupón debe tener estilo negro, y el notice de éxito/error debe quedar fijo en la parte inferior de la pantalla en mobile para que siempre sea visible.

## Contexto
El PDF da reglas de diseño específicas para el cupón: botón negro y un notice de error/éxito fixed bottom en mobile para que no "salga en el piso" o quede oculto. Actualmente el feedback del cupón puede quedar oculto en mobile por el layout del checkout.

## Archivos a revisar
- `js/coupons.js` — lógica del cupón y `showNotice()`
- `inc/ajax/coupons-actions.php` — handler AJAX del cupón
- `style.css` — estilos del botón de cupón y notice
- `woocommerce/cart/cart.php` — si tiene bloque de cupón custom
- `page-checkout.php` — template del checkout

## Implementación exacta
1. En CSS: estilizar el botón de aplicar cupón en negro:
   ```css
   .bsc-coupon-submit,
   #coupon_code + button,
   .coupon [type="submit"] {
       background: #000;
       color: #fff;
       border: none;
   }
   .bsc-coupon-submit:hover {
       background: #222;
   }
   ```
2. En `coupons.js`, la función `showNotice()` debe crear un elemento con clase `.bsc__coupon-notice` para el mensaje de éxito/error.
3. En CSS, estilar `.bsc__coupon-notice` como fixed bottom en mobile:
   ```css
   .bsc__coupon-notice {
       display: none;
       padding: 12px 16px;
       border-radius: 4px;
   }
   .bsc__coupon-notice.success { background: #d4edda; color: #155724; }
   .bsc__coupon-notice.error   { background: #f8d7da; color: #721c24; }
   @media (max-width: 767px) {
       .bsc__coupon-notice {
           position: fixed;
           bottom: 16px;
           left: 16px;
           right: 16px;
           z-index: 9999;
       }
   }
   ```
4. En `coupons.js`, mostrar el notice con un auto-hide de 4 segundos:
   ```javascript
   function showNotice(message, type) {
       const $notice = $('.bsc__coupon-notice');
       $notice.removeClass('success error').addClass(type).text(message).show();
       setTimeout(() => $notice.hide(), 4000);
   }
   ```
5. Verificar que el cupón sigue funcionando correctamente (no solo la UI).

## Qué NO se acepta como solución
- Usar `alert()` para mostrar mensajes de cupón.
- Notice que queda permanentemente visible (sin auto-hide).
- Cambiar la lógica del handler PHP del cupón.

## Requerimientos
- El botón de cupón debe ser negro en desktop y mobile.
- El notice debe ser visible siempre en mobile (fixed bottom).
- Auto-hide a los 4 segundos.

## Criterios de aceptación
- Botón "Aplicar cupón" es negro con texto blanco.
- Al aplicar cupón válido: notice verde visible en mobile (fixed bottom).
- Al aplicar cupón inválido: notice rojo visible en mobile (fixed bottom).
- El notice desaparece solo después de 4 segundos.
- El cupón sigue aplicándose correctamente.

## QA manual
- En checkout mobile: ingresar cupón válido → botón negro → notice verde fixed bottom.
- En checkout mobile: ingresar cupón inválido → notice rojo fixed bottom.
- El notice desaparece solo después de ~4 segundos.
- Verificar en desktop: notice no fixed, solo inline.

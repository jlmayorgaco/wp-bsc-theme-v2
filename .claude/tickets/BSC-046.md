# BSC-046 — Runbook de restore y disaster recovery

## Objetivo
Documentar el procedimiento exacto para restaurar el sitio desde un backup: pasos de restauración de DB, pasos de restauración de archivos, checklist de validación post-restore y tiempos estimados (RTO/RPO).

## Contexto
Tener backups sin saber cómo restaurarlos es tan peligroso como no tener backups. Este runbook debe ser ejecutable por cualquier persona del equipo técnico en una situación de emergencia, sin necesidad de conocimiento previo del sistema.

## Archivos a revisar/crear

## Implementación exacta
1. Crear `docs/runbook-restore.md` con las siguientes secciones:

### Pre-requisitos
- Acceso SSH al servidor.
- Credenciales de DB.
- Acceso al almacenamiento de backups (local o remoto).

### Restaurar solo la base de datos
```bash
# 1. Detener el sitio (poner en modo mantenimiento)
wp maintenance-mode activate --path=/var/www/html

# 2. Restaurar el dump
gunzip -c /backups/bsc/db/db-FECHA.sql.gz | mysql -u USER -pPASS DBNAME

# 3. Verificar tablas
mysql -u USER -pPASS DBNAME -e "SHOW TABLES;"

# 4. Quitar modo mantenimiento
wp maintenance-mode deactivate --path=/var/www/html
```

### Restaurar archivos (uploads + theme)
```bash
# 1. Ir al directorio raíz
cd /var/www/html

# 2. Extraer el backup
tar -xzf /backups/bsc/full/full-FECHA.tar.gz

# 3. Ajustar permisos
chown -R www-data:www-data wp-content/
chmod -R 755 wp-content/
```

### Checklist de validación post-restore
- [ ] Home carga correctamente.
- [ ] Se puede agregar producto al carrito.
- [ ] El checkout procesa correctamente.
- [ ] Las imágenes de productos cargan.
- [ ] El admin de WordPress es accesible.
- [ ] Los plugins activos están activos.
- [ ] WooCommerce no muestra errores.

### RTO/RPO estimados
- **RPO (pérdida máxima de datos)**: 24 horas (backup diario de DB).
- **RTO (tiempo de restauración)**: 30-60 minutos para restauración completa.

- Sin checklist de validación post-restore.
- Sin estimado de RTO/RPO.

## Requerimientos
- Los comandos deben ser ejecutables en el servidor de producción real.
- El documento debe estar en formato Markdown legible.

## Criterios de aceptación
- El runbook tiene pasos para: restaurar DB, restaurar archivos, validar post-restore.
- Los comandos son específicos (no genéricos) para el proyecto BSC.
- El checklist de validación tiene al menos 7 items.
- El RTO/RPO está documentado.

## QA manual

# BSC-048 — Hardening básico WordPress/WooCommerce

## Objetivo
Aplicar una capa mínima de hardening de seguridad: proteger el login, deshabilitar XML-RPC si no se usa, ajustar permisos de archivos y reducir la exposición de información innecesaria.

## Contexto
El proyecto tiene varios problemas de seguridad identificados en ISSUE.md. Antes del deploy a producción es necesario cerrar las vulnerabilidades más evidentes. Este ticket cubre las medidas de seguridad a nivel de aplicación WordPress, no de servidor.

## Archivos a revisar
- `functions.php` — deshabilitar features innecesarias de WP
- `.htaccess` — reglas de seguridad (si el hosting usa Apache)
- `inc/setup/theme-setup.php` — features de WP ya deshabilitadas

## Implementación exacta
1. En `functions.php`, agregar (si no existen ya):
   ```php
   // Deshabilitar XML-RPC
   add_filter('xmlrpc_enabled', '__return_false');
   
   // Remover versión de WordPress del HTML
   remove_action('wp_head', 'wp_generator');
   
   // Deshabilitar REST API para usuarios no logueados (cuidado: puede romper WooCommerce)
   // Solo deshabilitar rutas sensibles:
   add_filter('rest_authentication_errors', function($result) {
       if (!is_user_logged_in() && !is_rest_request_public()) {
           // No deshabilitar completamente, solo el endpoint /users/
       }
       return $result;
   });
   
   // Limitar intentos de login (si no hay plugin)
   add_action('wp_login_failed', 'bsc_login_failed');
   function bsc_login_failed($username) {
       $ip = $_SERVER['REMOTE_ADDR'];
       $key = 'bsc_login_fail_' . md5($ip);
       $fails = (int) get_transient($key);
       set_transient($key, $fails + 1, 15 * MINUTE_IN_SECONDS);
       if ($fails + 1 >= 5) {
           // Bloquear temporalmente
       }
   }
   add_filter('authenticate', 'bsc_block_login', 30, 3);
   function bsc_block_login($user, $username, $password) {
       $ip = $_SERVER['REMOTE_ADDR'];
       $key = 'bsc_login_fail_' . md5($ip);
       $fails = (int) get_transient($key);
       if ($fails >= 5) {
           return new WP_Error('too_many_retries', 'Demasiados intentos fallidos. Intenta en 15 minutos.');
       }
       return $user;
   }
   ```
2. Verificar permisos de archivos/carpetas en el servidor:
   - `wp-config.php`: 640 o 600.
   - `wp-content/`: 755.
   - Archivos PHP: 644.
   - Documentar comandos en `docs/security-checklist.md`.
3. En `.htaccess`: agregar reglas para bloquear acceso directo a archivos PHP en uploads:
   ```apache
   # Bloquear PHP en uploads
   <FilesMatch "\.php$">
       Order Deny,Allow
       Deny from all
   </FilesMatch>
   ```
4. Crear `docs/security-checklist.md` con el estado de cada medida de hardening.

## Qué NO se acepta como solución
- Deshabilitar REST API completamente (WooCommerce lo usa).
- Reglas `.htaccess` que rompan el sitio (probar en staging primero).
- Implementar sin probar en entorno local.

## Requerimientos
- Ninguna medida de seguridad debe romper el checkout o el carrito.
- Probar todas las medidas en staging antes de aplicar en producción.

## Criterios de aceptación
- XML-RPC está deshabilitado.
- La versión de WordPress no aparece en el HTML.
- El login tiene límite de intentos (5 fallos → bloqueo de 15 min).
- Los permisos de archivos son correctos.
- PHP en uploads está bloqueado.

## QA manual
- Ir a `/xmlrpc.php` → debe retornar error 403 o 405.
- Inspeccionar HTML de la home → no debe haber `<meta name="generator"`.
- Intentar login incorrecto 5 veces → debe aparecer el mensaje de bloqueo.
- Subir un archivo `.php` a uploads e intentar accederlo → debe ser bloqueado.
- Verificar que el checkout sigue funcionando.

# BSC-053 — Email notifications custom para todos los estados de pedido

## Objetivo
Crear templates de email custom con diseño BSC para cada cambio de estado de pedido: confirmación de pago, en preparación, enviado, entregado, cancelado. Reemplazar los emails genéricos de WooCommerce.

## Contexto
BSC-033 cubre el email de envío con tracking. Este ticket cubre el sistema completo de emails para todos los estados del pedido. Los emails de WooCommerce por defecto no tienen branding BSC y son genéricos. El cliente necesita emails que refuercen la marca.

## Archivos a revisar
- Nuevo `emails/bsc-emails.php` — configuración del sistema de emails
- Nuevos templates en `emails/` — uno por estado
- `inc/woocommerce.php` — hooks de cambio de estado

## Implementación exacta
1. Crear los templates de email en `emails/`:
   - `emails/bsc-order-confirmed.php` — Pago recibido
   - `emails/bsc-order-preparing.php` — En preparación
   - `emails/bsc-order-shipped.php` — Enviado (con tracking, reusar de BSC-033)
   - `emails/bsc-order-delivered.php` — Entregado
   - `emails/bsc-order-cancelled.php` — Cancelado
2. Cada template HTML debe tener:
   - Header con logo BSC.
   - Mensaje personalizado según el estado.
   - Resumen del pedido (productos, total).
   - Datos de contacto y WhatsApp para soporte.
   - Footer con links a redes sociales y políticas.
3. Crear `emails/bsc-emails.php` con la función `bsc_send_order_email($order_id, $status)`:
   - Mapeo de status → template.
   - Llamada a `wp_mail()` con `Content-Type: text/html`.
4. En `inc/woocommerce.php`: hook en `woocommerce_order_status_changed` para disparar el email BSC:
   ```php
   add_action('woocommerce_order_status_changed', 'bsc_handle_order_status_email', 10, 3);
   function bsc_handle_order_status_email($order_id, $old_status, $new_status) {
       $status_map = [
           'processing' => 'confirmed',
           'preparing'  => 'preparing',
           'shipped'    => 'shipped',
           'completed'  => 'delivered',
           'cancelled'  => 'cancelled',
       ];
       if (isset($status_map[$new_status])) {
           bsc_send_order_email($order_id, $status_map[$new_status]);
       }
   }
   ```
5. **Importante**: desactivar los emails nativos de WooCommerce para los estados que se cubren con BSC emails, para evitar emails duplicados:
   ```php
   add_filter('woocommerce_email_enabled_customer_processing_order', '__return_false');
   add_filter('woocommerce_email_enabled_customer_completed_order', '__return_false');
   ```

## Qué NO se acepta como solución
- Emails sin diseño BSC (usar el template HTML de WooCommerce genérico).
- Enviar emails duplicados (BSC + WooCommerce nativo para el mismo estado).
- Email sin resumen del pedido.

## Requerimientos
- Todos los emails deben tener `Content-Type: text/html; charset=UTF-8`.
- Los emails deben incluir el número de pedido y los productos.
- Desactivar los emails nativos de WooCommerce para los estados cubiertos.

## Criterios de aceptación
- Cambiar estado a "Procesando" → cliente recibe email BSC de confirmación de pago.
- Cambiar estado a "Enviado" → cliente recibe email con tracking.
- Cambiar estado a "Completado" → cliente recibe email de entrega.
- Los emails tienen diseño BSC reconocible.
- No se reciben emails duplicados.

## QA manual
- Crear pedido de prueba → completar pago → verificar email de confirmación BSC.
- Cambiar estado a "En preparación" → verificar email recibido.
- Agregar tracking → verificar email de envío con número de tracking.
- Completar el pedido → verificar email de entrega.
- Verificar que NO llega el email genérico de WooCommerce.

# BSC-040 — Eliminar N+1 queries en product card y taxonomías

## Objetivo
Reducir el número de queries en los loops de productos usando `update_post_meta_cache` y `update_object_term_cache` para pre-cargar términos y meta en batch, en lugar de una query por producto.

## Contexto
El issue (PERF-003) detecta que `card.php` llama `get_the_terms()` individualmente por cada producto en el loop, y `slider.php` también ejecuta queries adicionales por producto. En una página con 20 productos esto puede generar 40+ queries extras.

## Archivos a revisar
- `components/products/card.php` — uso de `get_the_terms()` por producto
- `components/products/slider.php` — queries adicionales por producto
- `inc/ajax/filters-actions.php` — loop de productos en filtros AJAX

## Implementación exacta
1. En cualquier lugar donde se ejecuta un `WP_Query` de productos seguido de un loop con `get_the_terms()`, agregar los flags de pre-carga:
   ```php
   $products_query = new WP_Query([
       'post_type'           => 'product',
       'posts_per_page'      => 20,
       'update_post_meta_cache' => true,  // pre-carga meta
       'update_post_term_cache' => true,  // pre-carga términos
       // ... resto de args ...
   ]);
   ```
2. Verificar que estos flags están habilitados (son `true` por defecto en WP_Query, pero confirmar que no se están deshabilitando explícitamente).
3. En `components/products/slider.php`: verificar que la query incluye `update_post_meta_cache => true` y `update_post_term_cache => true`.
4. En `inc/ajax/filters-actions.php`: verificar que la query también tiene estos flags.
5. En `card.php`: si hay `get_post_meta()` adicionales por producto, verificar que están cubiertos por el meta cache de la query padre.
6. Eliminar `orderby => 'rand'` de `slider.php` si existe (causa full table scan). Reemplazar por `orderby => 'date'` o `orderby => 'modified'`.

## Qué NO se acepta como solución
- Cambiar la lógica de negocio del card o slider.
- Eliminar datos que se muestran en el card.
- Deshabilitar `update_post_meta_cache` o `update_post_term_cache`.

## Requerimientos
- No cambiar qué datos se muestran, solo cómo se cargan.
- Eliminar `orderby => 'rand'` si existe (performance crítica).

## Criterios de aceptación
- El número de queries en la home con 20 productos se reduce notablemente (verificar con Query Monitor).
- Las categorías y meta de los productos se cargan en batch.
- Los products cards siguen mostrando la misma información.

## QA manual
- Activar Query Monitor en staging → ir a la home → anotar número de queries.
- Aplicar los cambios → volver a medir → el número debe reducirse significativamente.
- Verificar visualmente que las cards de productos no cambiaron.
